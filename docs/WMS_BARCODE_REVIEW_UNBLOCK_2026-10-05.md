# 官網商品核對及處理中訂單修正

## 本次問題

Shopify 同品號 `4711299274732` 有兩個目前商品頁面，兩者條碼均為 `4711299274732`、規格均為 iPhone 18 Pro。WMS 使用的 ECOUNT 對照檔有唯一啟用品項，但條碼欄空白。舊程式將多版本列入核對，核對規則卻只允許單一版本及非空白 ERP 條碼，造成核對與下載均無法操作。

## 修改

- 同品號的多個有效 Shopify 版本若來源條碼一致，可由有權限人員核對實物後保存對照。來源條碼不同、缺少版本、ERP 停用或多重匹配仍阻擋。
- ERP 條碼空白保持空白，核對後使用來源 API 的實際條碼供 WMS 掃碼；不推測條碼、不修改 ERP 主檔、不刪除 NEW 前綴或尾碼。
- 核對保存完整版本集合及 ERP 品號、條碼、名稱、規格。版本集合或任一對照資料變更，舊核對失效；既有單版本紀錄相容，不需 migration。
- 核對區可展開相關訂單，顯示來源訂單號、完整商品名稱、數量及 Shopify 訂單連結。連結只使用已核對的店鋪網域與訂單 ID。
- Shopify `IN_PROGRESS`、`OPEN`、`PENDING_FULFILLMENT` 僅在所有有效商品尚未出貨時納入，原始 API 狀態保留。付款及 COD 規則不變，部分出貨、暫停及排程不自動銷整單。

## 人員操作

1. 上傳商城原始訂單，系統即時查核。
2. 若有商品例外，開啟相關訂單並核對商品實物，確認後保存商品對照。
3. 下載銷貨檔，行政人員上傳 ECOUNT 並確認銷货；庫存只在 ECOUNT 正式交易扣除。
4. 匯回 ECOUNT 理貨／出貨單，WMS 核對通過後，倉儲主管列印預揀總表及逐筆訂單明細，接續揀貨及裝箱複檢。
