## 轉檔與作業方式

1. 1Shop 只勾選指定兩筆 TEST 訂單，匯出範圍選「已選擇：2 個」，格式選 Excel 2007。
2. DEV 出貨管理開啟「1Shop 訂單轉檔」，選原始檔。轉檔頁在瀏覽器記憶體中處理，不提交業務 API，也不保存個資。
3. 核對 2 筆、4 商品列、4 件及 1,427 元。預揀視圖是 3 種 SKU，明細仍保留每筆來源訂單。
4. 確認商品對照、ERP 客戶、倉庫、日期、唯一測試追蹤單號、含稅交易設定；保留未付款狀態。補齊阻擋項目後下載 ECOUNT 27 欄銷貨檔。
5. ECOUNT 輸入銷貨單使用既有「WMS商城訂單明細」格式，從線上上傳資料載入。儲存前核對 4 實體商品列與 1 運費列；商品數量共 4，含運費的財務合計共 1,427。
6. 銷貨只能儲存一次。若結果不明，先用測試追蹤單號查詢，不重新上傳扣庫。確認實際銷貨單號與庫存差額後，再產生或查找同來源理貨單。
7. 理貨單保留四個實體商品列與商城單號／平台／店鋪／來源明細號。運費屬會計用途，不應成為 WMS 待揀商品。是否由 ECOUNT 自動排除，必須以實際匯出驗證。
8. 使用「WMS商城訂單匯出」下載本批理貨明細，核對條碼完整後，才從既有 DEV 匯入入口建立 WMS 批次與商城子单，再列印 WMS 工作單條碼。

原始檔沒有「產品分類」欄，已有「銷售頁名稱／前綴」及「名稱」組合描述。三者保留各自意義；團組分類若另由主檔提供，不拿來取代 SKU 或合併不同商品。

## 驗收界線

此次前端轉檔不提供跨人員持久轉檔紀錄或跨批次重複銷庫防護。來源明細識別碼可在相同內容重排後保持一致，但來源內容變動會變碼，不等於平台原生明細 ID。

正式站、資料庫與 API 映像不在本次修改範圍。DEV 更新只發布前端；Cloud Run 新 revision 仍會啟動既有 API sidecar。轉檔單元測試、本機瀏覽器驗證、DEV 部署、ECOUNT 實際儲存／扣庫、WMS 實物掃碼須分別記錄，不可相互替代。
