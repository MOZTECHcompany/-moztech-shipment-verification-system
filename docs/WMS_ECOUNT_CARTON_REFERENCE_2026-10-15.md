# ECOUNT 原銷貨單與 WMS 箱號對照

## 唯一扣庫界線

ECOUNT 保留正式銷貨及庫存帳。已建立 ECOUNT 銷貨單後匯入 WMS 的理貨單，只執行倉內核對。WMS 本功能不呼叫 ECOUNT、不新增銷貨、不調整原銷貨數量，也不產生第二次庫存扣帳。

箱號代表實物容器；品號、商品國際條碼、實際 SN、理貨單號與 ECOUNT 銷貨單號分開保存，不能互相代替。理貨單號不會自動當成已核對的 ECOUNT 單號。

## 銷貨人員流程

1. 依原流程匯入理貨單、揀貨與裝箱。訂單內的 ECOUNT 銷貨對照列出本次實際使用的箱號、品號和數量。
2. 複製 WMS 出貨編號及箱號摘要，或匯出已裝箱對照，供原 ECOUNT 銷貨單補充追溯資料。不能把對照檔上傳成新的銷貨單，也不能新增箱號品項列來扣數量。
3. 記錄公司的 ECOUNT 代碼與原銷貨單號。未完成核對時只保存參考，不宣稱 ECOUNT 已收到或庫存已入帳。
4. 完成原單上的追溯資料後，銷貨人員可使用原單已儲存的品號、數量及實際 SN 做人工明細核對。系統比對 WMS 的核對量，記錄當時的人員、內容版本和結果。外部明細不會用 WMS 數據自動預填。

例如同一商品出 25 件：N1 出 5、N2 出 10、N3 出 10；原銷貨單仍是 25 件。WMS 保存各箱的分配來源與當時內容版本，不另外建立 25 件銷貨。

同品號有多個來源明細時，完整對照保留每個 WMS 明細 ID、箱分配 ID、來源身分及實際 SN。普通散件另外標示未使用箱號；不能虛構箱號補齊。SN 保持原大小寫、前導零與符號，不以箱號取代 SN。

## ECOUNT 實際欄位配置

2026/10/15 在已登入的公司 ECOUNT 畫面建立獨立輸入格式「WMS箱號出貨對照」，複製原「WMS商城訂單明細」後新增既有「文字型1」，顯示名稱為「WMS箱號明細」，啟用換行。原格式及既有商城來源欄位保留；未修改既有銷貨資料、數量或庫存。

銷貨人員在既有銷貨單選用新格式，將對應品項的箱號及取用件數補在「WMS箱號明細」。全單追溯 Excel 可留作原單附件，不得透過銷貨資料匯入新增第二張單。完整摘要含多品項時，不可將全單總數當成每個品項的出貨量。文字長度不足時使用附件保留完整明細，不截斷 SN 或箱號。

ECOUNT 的「詳細」欄是詳細品項／BOM 功能，不是追溯文字欄，本格式不使用。全域新增欄位設定頁當時顯示更新中，因此使用已存在的文字欄；不聲稱已啟用自動 API 回寫。

人工核對支援至多 10,000 列及 10,000 個實際 SN，專用請求上限 2 MiB。超過上限明確拒絕，不截斷或四捨五入。既有 API 的請求上限不受影響。

## 狀態與保護

未關聯、僅記錄參考、已人工核對及內容已變分開顯示。「已人工核對」是人員對原單明細的確認，並非 ECOUNT 官方 API 的寫入成功回執；本輪不啟用自動回寫。

正式對照只計有效已裝箱的分配。已揀貨但未裝箱、已解除的分配保留在完整歷史，不加進本次出貨總數。待異動、作廢、尚未完成核對的訂單不能確認完成。負數沖正／混合單仍保留原有核對功能，不能套用正數箱號銷貨確認。

對照使用獨立內容指紋，包含訂單品項、核對數量、箱號、箱內容版本、分配、實際 SN 及來源身分；不使用受其他訂單取貨影響的當前箱餘量。相關內容變動後，需要重新核對；不能沿用舊確認。

指令在送出前保留識別。相同指令重送不重複寫入，回傳最新對照狀態，避免沿用過期確認；識別相同但內容不同、舊版本、錯誤數量或 SN 均拒絕。訂單、箱餘量及原有核對進度不受對照紀錄寫入影響。

人工核對目前以一張完整 ECOUNT 原銷貨單為範圍。同公司、同日期及序號的原單不可重複確認給不同 WMS 訂單；空格、日期分隔和序號前導零會正規化。多筆 WMS 分批對應一張原單時，須另行處理合併核對範圍，不能把單筆確認當成全單一致。

同一原單僅改寫日期分隔或前導零，再按保存參考，不會清除既有人工核對、洗掉出貨內容變動提示，或釋出已關聯原單。要確認變動後的出貨內容，仍須重新提供原單實際明細。

銷貨／拋單人員與各類管理員可維護對照，揀貨／裝箱人員可查看。使用伺服器當前帳號權限，保留實際操作人及不可覆寫的異動歷史，不更動原帳密或工序權限。

## 維護入口

- `GET /api/orders/:orderId/ecount-reference`：同一資料快照的箱分配、散件、各品號實際量、內容指紋、參考／人工核對狀態及輕量歷史。讀取不變更核對進度。
- `POST` 同一路徑：傳入 `commandId`、`expectedActorId`、`expectedRevision`、`expectedFingerprint`、`companyCode`、`voucherNumber`；`confirmation: null` 僅記錄參考。
- 人工核對的 `confirmation.kind` 為 `manual-line-check`，必須提供外部原單 `lines`（品號、數量、實際 SN）及 `acknowledgeExistingSales`、`acknowledgeMetadataSaved`。伺服器不替外部證據補值。
- Migration `042_ecount_carton_references.sql` 新增 `wms_ecount_order_references`、`wms_ecount_reference_history`、`wms_ecount_reference_commands`；完整當時出貨及外部證據保存在資料庫，列表不重複載入大筆證據。
- 主要程式為 `ecountReferenceManifest.js`、`ecountReferenceService.js`、`EcountReferenceCard.jsx`。單元測試納入原本後端／前端指令；真 PostgreSQL、HTTP、Chrome／Excel 驗收檔以 `ecount-reference` 命名，只允許隔離的 loopback 合成測試資料。

## 外部驗收界線

ECOUNT 欄位配置、原單補註、官方回執、庫存前後對帳，應分別留下實際證據。隔離的 WMS 測試、產生 Excel 或開啟 ECOUNT 頁面，不代表已完成真實銷貨或庫存驗收。已有銷貨的訂單，不以再上傳銷貨檔作驗收。

資料表僅新增本地 ECOUNT 對照、歷史及防重送收據；保留既有資料。發版先檢查 schema、備份與原資料保留，再部署 0% 候選唯讀驗收，通過後切換。回復保留所有新紀錄，不還原舊 dump 覆蓋運行中的資料。
