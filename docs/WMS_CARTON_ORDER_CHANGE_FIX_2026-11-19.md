# 箱號與訂單異動相容修正

本次維護基準為 WMS 正式版 `a00d59f8ea90f743f1fdebb7eee3ceed51c82c99`，不修改 ERP 或 ECOUNT 過帳。

## 原因與修正

訂單異動原本套用舊 SN 直接編輯的保護，凡是已登記箱內容的 SN 都會拒絕，連尚未揀貨、僅將無 SN 數量改為指定 SN 的主管核可也被擋住。現在核可只更動訂單需求；以相同的 SN 鎖確認來源商品、可用狀態及其他訂單占用，不更動箱內 SN、餘量或確認狀態。

原本整張單只要有任何箱號分配就不能核可。現在只阻擋涉及已分配品項的異動，其他散件可以核可。刪單仍檢查整張單；已揀貨或已裝箱的相關品項仍須走解除分配／實物更正流程。直接更換箱內 SN 的舊編輯入口仍受保護。

完整移除再新增同條碼、切換有無 SN 時，保留唯一原始列的品號、掃描碼及來源資料，避免「樣品」品號被改成國際條碼，或遺失來源 SKU／單號／行號。原有不允許同列部分切換有無 SN 的限制不變。

## 舊箱的相容界線

正式只讀查核發現，一些尚未確認的箱已經有 SN 走舊單件流程揀貨／裝箱。這些箱的匯入數量與舊出貨紀錄尚未對帳，不能把顯示的箱內剩餘量視為已驗證的實物庫存。

此修正保留原有單件 SN 流程，避免強制重新確認整箱而阻擋在途出貨。核可不會擅自確認這些箱，也不回填或捏造歷史箱分配。已確認箱仍以箱分配流程作業；拆箱裝箱須逐件掃 SN，完整未拆原箱才可掃箱號。

舊箱後續必須逐箱比對既有出貨 SN、目前實物及原箱內容，建立可追溯的更正後才能啟用其正確箱餘量。不得直接重設已取出 SN 為可用，或把匯入數量當成新進貨。

## 驗證與操作

`backend/tests/cartonOrderChange.test.cjs` 使用一次性資料庫與實際 HTTP 路由驗證主管權限、核可防重送、整筆失敗回復、來源商品不符、其他單占用、不可用 SN、內部掃描碼、原品號保留，以及兩種後續出貨路徑：

- 未使用草稿箱：確認內容後逐件揀貨／裝箱，出貨記錄有來源箱及實際 SN，重掃不重扣箱內餘量。
- 有歷史單件出貨的未確認箱：可核可另一個未使用 SN，繼續原單件揀貨／裝箱；重送不重計數，維持未確認箱狀態，不冒稱其餘量已對帳。

PGlite 會序列化交易；重送測試不是實際多連線 PostgreSQL 鎖競爭的驗收。實體掃描器仍由現場測試。正式單據由倉庫主管自行核可，本次不代核可或出貨。

發布需使用乾淨提交、精確映像 digest、0% 候選核對及流量讀回；實際版本與測試結果另存發布收據。無資料庫 migration。
