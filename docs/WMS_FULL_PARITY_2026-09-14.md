## 本次修補的功能障礙

1. 還原訂單備註／討論預設可見，讓置頂備註不再被收合區塊藏住。
2. 留言回覆／更多操作放回訊息區域內，解決窄欄釘選按鈕被裁掉、按不到；釘選區可捲動、輸入框保留空間，避免多則釘選擠掉輸入與送出操作。
3. 還原新品不良、出貨標籤、揀貨單與匯出明細的直接入口，以及 SKU 完成度。
4. 新品不良入口遵循舊後端管理／自己拋單權限；使用不修改訂單的 snapshot 載入表單，防止關閉後舊回應污染表單，禁止連點提交。
5. 新品不良紀錄補上原憑證與返回訂單，修正 CSV 引號與換行，載入失敗不再顯示成「沒有紀錄」。
6. 最高管理員可依原前端設計收回／刪除他人留言，修正後端只認 admin 的不一致。
7. 刷錯分析保留原 ISO 時間區間合約，修正新版查詢驗證器造成的 400；報表仍維持日期格式的邊界驗證。

## 保留的合理差異與尚不能冒充完成的項目

- 使用者先前明確要求的 Corely AI 品牌、左下設定、側邊欄縮放與新的工作台設計保留；本次不把舊品牌、硬編碼示範使用者或正式 Render 連線拷回。
- `TaskComments-modern.jsx` 才是舊工作區真正載入的討論元件。`TaskComments.jsx`、`TaskComments-old.jsx`、`TaskDashboard-with-batch.jsx`、未掛載的批次列印／時間軸等備份，不宣稱它們都是舊站實際可用入口；檔案掃描有涵蓋。
- 6 個除錯／初始化／維護 HTTP 入口改為受控離線 migration／bootstrap／retention，防止正式應用請求任意變更資料結構。對應 productionMaintenance／databaseBootstrap／migrationRunner 測試，不能为了「路由同名」重新開放。
- 舊 Render 已確認缺失的兩份附件內容仍無法憑空恢復，metadata 保留。沒有原檔就不能宣稱附件資料 100% 完整。
- 音效／通知等 localStorage 偏好屬原瀏覽器與網域，非 PostgreSQL；新站的相機、通知與實體印表機需要現場驗證。自動測試只能證明解碼及列印文件，不能證明紙張有印出。
- 此次比對基準是使用者提供的 Render／GitHub WMS repo；交接未提供的 AI Studio 私人 Cloud Run 前端不能宣稱已完成逐行來源比對。
- 不自動扣庫存。ECOUNT、AI ERP、綠界物流、金流及銷退不是本次為恢復舊 WMS 功能而擅自啟用的操作。
- 正式資料庫的現況以 2026-09-14 唯讀紀錄為準：4,571 訂單、30,607 品項、46,970 SN、191,264 日誌、273 例外、71 新品不良、1,125 留言、1,072 提及、853 已讀、4 訂單釘選、24 使用者。用户可能在搬遷後管理帳號，不為對齊歷史 25 人快照而覆寫現况。
