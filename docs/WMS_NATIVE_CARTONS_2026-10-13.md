# 現用 WMS 自建箱號與 ECOUNT 過渡流程

以正式 main `925b607`（2026/10/13 雙工序與交接）整合箱號功能；原生登入與現有理貨單匯入為入口，新 ERP 匯出是選用功能。

## 現場操作

1. 倉儲管理員進入「箱號管理 → 新增箱號」。箱號自動產生且可自行命名，一個外箱使用一個唯一箱號。
2. 搜尋已匯入的 WMS 品項，選取實際品號／型號和品名。原匯入掃描碼不自動視為國際條碼；與實物確認後可選國條／內碼，也可只使用品號。無歷史品項時可手動填入與理貨單相同的 WMS 品號／型號。
3. 無 SN 箱填實際數量，例如 10；有 SN 箱貼入完整逐件 SN 清單並填一致數量，保留大小寫與前導零。草稿可修改，確認箱內內容後封存。
4. 列印外箱 QR 貼紙。QR 僅保存 `CARTON:箱號`，揀貨／拆箱後的剩餘內容由 WMS 查詢。
5. 按原本方式把 ECOUNT 銷貨／理貨單匯入 WMS，認領正確工序。在原掃描欄掃箱 QR，可一次核對整箱；需求不足整箱時須用「掃箱／拆箱」明確輸入數量或選實際 SN。
6. 裝箱員明確認領裝箱後掃同箱核對，沿用原分配，不再次減少箱內餘量。同一帳號可依最新工作模式執行兩工序，暫停與交接保留。
7. 訂單「箱號明細 → 匯出對照」保存箱、品項、數量／逐件 SN 與原匯入單號的追溯；此對照檔不作為第二張銷貨單匯入。

ECOUNT 繼續負責正式銷貨／庫存帳。WMS 掃箱更新倉內核對及箱剩餘量，不額外建立 ECOUNT 銷貨或再次扣正式庫存；現用 ECOUNT 檔案／品號設定仍需現場對齊，系統沒有自動修改 ECOUNT。

## 驗證與發布

驗證在獨立合成資料執行：原生 UI 建箱在匯入理貨單之前完成；國條 SN 箱、無國條無 SN 箱各 10 件，實際 QR 圖像解碼、ECOUNT 格式 XLSX 匯入、原掃描欄核對、同帳號認領兩工序與精確 SN 展開均驗證。正負匯入、舊流程、角色、暫停與交接回歸保留。

Migration `040_wms_cartons.sql` 只新增箱資料表及訂單品項兩個欄位；保持已有 `031_worker_modes.sql`。部署先在獨立 DEV schema 驗證，再以相同 image digest 建正式 0% 候選，正式切流前重讀 runtime 和資料快照。發布回執另存協調目錄。實體條碼槍、紙張、現場原始 ECOUNT 檔案和實際箱內物品由現場驗收。

新箱資料開始使用後，不可直接回復不含箱分配保護的舊映像繼續作業；應使用相容箱資料和 031 工序狀態的修正映像。保留資料庫和歷史紀錄，不能刪欄位／箱資料或還原舊 dump。
