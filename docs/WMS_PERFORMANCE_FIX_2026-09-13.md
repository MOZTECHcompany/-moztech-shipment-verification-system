# WMS 掃碼、報表與大量資料效能修正

以 `53e76dc787881033e05d15735b2ffd9ebb94f176` 為基準，隔離分支 `codex/wms-performance-20260913`。範圍是 WMS；不改 ERP、Render、物流契約或庫存扣帳。

## 修改

- 報表改為 SQL 彙總、每批 200 筆串流 CSV，重用時間格式器。同一資料庫同時一份報表，其他下載回覆可重試的 429；總 DB_POOL_MAX 仍為 3，其中報表 1、作業 2。
- 查詢採有限佇列與 SQL 期限；操作紀錄上限 1,000，日期驗證包含完整台灣日。新增四個正規化搜尋 GIN 索引。
- 掃碼工作區改用 SELECT-only 快照。新版掃碼以 UUID、狀態摘要與同交易收據防止重送重複計數，只回傳變動品項／SN。舊版完整回應介面保留。失去回應時只以相同識別重試一次；狀態衝突須重新核對。
- 展開 SN 使用虛擬清單。留言提及通知延後至交易提交。慢請求紀錄處理時間、連線池等待和記憶體，不寫入條碼或顧客資料。

## 本機驗證

150 項後端 Jest、95 項前端、13 項真 PostgreSQL 倉庫回歸（含 500 揀貨＋500 裝箱）、8 項新效能／防重送整合測試、8 項 migration/bootstrap 測試通過；前端建置通過。效能日誌另補一項真 Express 掛載路由回歸測試，通過並已在候選 Cloud Logging 取得取樣。ECPay 組合執行曾有 HTTP parser 暫態失敗，獨立重跑 6 項全過；物流程式未改。

隔離 PostgreSQL、十倍歷史資料，非正式效能保證：

| 情境 | 結果 |
| --- | --- |
| 20 人各 60 次掃碼＋持續短字搜尋 | 1,200 次成功，稽核 1,200 筆；p95 165 ms |
| 100 次掃碼＋3 個同時報表要求 | 掃碼 p95 11.5 ms；1 份成功，2 份明確 429 |
| 十倍歷史完整報表 | 中位 2.33 秒，API 約 158 MiB RSS |
| 1,000 品項／10,000 SN，60 揀＋60 裝 | 全部成功，p95 63／65 ms；每次 747 bytes |

原問題重現時三份報表曾使 RSS 達約 1.82 GiB、掃碼 5.35 秒失敗；改善後透過限制同時匯出保留掃碼資源，不表示三份報表可同時產生。大型 SN 原回應約 2.13 MB。

## 發布與回復

先在私有驗證 Cloud Run 與獨立驗證資料庫執行，再更新正式 `corely-wms`。正式資料库先備份；026 只新增掃碼收據表。027 的四個索引先於交易外以 `CREATE INDEX CONCURRENTLY` 建立並確認有效，再執行正式 migration runner 記錄 checksum；啟動服務不執行 migration。pg_trgm 僅安裝於指定 WMS 資料庫。

保留舊 revision `corely-wms-cutover-20260913`，不刪收據、索引或回灌資料。舊版 schema readiness 接受額外 migration；不可執行舊版 migration runner。候選測試只在私有驗證 DB 建立合成單，正式只做唯讀驗證。

回復舊後端須先讓作業人員停止送出新掃碼、等所有待確認請求完成或核對，切回後所有工作站重新載入，才恢復掃碼。舊後端不認識新版 UUID 收據，因此不能在新版頁面仍持續掃碼時直接混合新舊後端流量；不可自動無條件降版。若僅前端故障，可先保留新版後端，使用先前前端映像（舊掃碼回應介面仍相容）。

索引和流量操作依 [PostgreSQL 17](https://www.postgresql.org/docs/17/sql-createindex.html) 與 [Cloud Run revision rollback](https://docs.cloud.google.com/run/docs/rollouts-rollbacks-traffic-migration) 官方說明。

## 仍需後續驗收／演進

實體掃描器、倉庫網路、音效與印表機須實機驗收。10,000 SN 測試沒有逐筆掃完全部序號；只驗證前 60 筆各階段及超過 50 筆後的穩定性。訂單初次載入仍取完整資料，品項卡片尚未虛擬化；掃碼狀態核對仍讀整張訂單。收據不自動刪除，之後應依保留政策封存。跨實例 Socket／outbox、報表背景工作、大規模租戶隔離及 AI 客戶授權仍為後續架構工作。瀏覽器重載不保留未完成的掃碼 UUID，不宣稱離線佇列已完成。

實際建置、候選與正式發布狀態以協調目錄 `artifacts/wms-performance-fix-20260913/` 的發布紀錄為準。

私有 Cloud Run 已通過 400 次 API 掃碼、4 次重送防重複，以及 Chromium 真實頁面 60 次揀貨＋60 次裝箱；所有合成紀錄清除。正式唯讀驗證包含 4,541 筆完成歷史、4,571 筆報表及件數、25 位使用者和兩個物流帳戶設定。既有 24 張業務表逐列指紋全部一致。第一版效能修正 revision `corely-wms-perf-20260913` 已上線，可作為最終日誌補正版本的相容回復點；最終流量以 `release-final.json` 記錄為準。
