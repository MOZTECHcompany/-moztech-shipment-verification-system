# 商城銷貨回傳與預揀流程

## 人員操作

1. 出貨管理 → 商城訂單轉檔：上傳 Shopify／SHOPLINE／1Shop 原始檔，確認店鋪、商品與金額。
2. 「下載銷貨檔 → 上傳 ECOUNT」保存來源快照、建立每筆訂單固定 WT 工作條碼。下載不等於 ERP 已銷貨。
3. 行政在 ECOUNT 匯入並儲存。若本批已匯入，不可再次上傳；修正原單據。
4. 從批次卡片開啟「匯回 ECOUNT 銷貨明細」。選擇或拖入 ECOUNT 已儲存銷貨單的匯出檔，確認缺漏的商品條碼並勾選檔案來源，按「核對並建立預揀單」。核對全批來源明細、客戶、倉庫、商品、數量、稅前／稅額／含稅金額後建立獨立工作單，暫停認領直到預揀完成。WMS 產出的銷貨匯入檔與只有欄名的空白參考檔不能用來完成此核對；畫面會在選檔時提醒。若尚未送出銷貨，可展開「尚未上傳 ECOUNT」直接重下載本批銷貨檔，不必跳頁。
5. 主管／行政按「領單並列印」：登入人員記為領單人，可分別印全批預揀总表與每單分頁的訂單明細。首次開啟列印即記錄領單；取消列印、缺紙可重印，不重複建立任務。瀏覽器無法證明實體紙張已列印。
6. 指派揀貨員或裝箱員負責整批預揀。其工作台的「整批預揀作業」可查看批次；掃實物商品條碼並輸入實點數量。主管可記錄原因後將指定商品歸零重新清點。
7. 全部數量查核完成，由指派人按「完成預揀，放行各訂單揀貨」。每張訂單在作業看板以 WT 條碼認領揀貨，逐件掃產品／SN。
8. 揀貨完成後進入「二次查核要裝箱」，装箱員再次掃同張 WT 條碼認領並逐件複檢。保留獨立 picker、packer 與操作紀錄。
9. 封箱、物流建單／物流標籤與交寄仍按既有物流流程，不將倉內完成當成交寄或送達。

## ECOUNT 回傳格式

### 同批商品彙總銷貨（2026-09-17）

使用者已選擇以平台／店鋪的整批銷貨入帳，逐筆商城對帳仍保留於 WMS，後續由自有 ERP 處理。新版轉檔頁的新批次預設 `product-200-v1`；舊保存批次沒有此版本時，繼續下載原逐訂單格式，不因重下載而改變已送出銷貨的明細。

- 相同已核對 ERP 品項、規格、確認條碼、客戶、倉庫、稅別、幣別、平台、店鋪、日期及責任人，在同一批次內合併。保留完整品號前綴與尾碼，實物與非庫存運費分開。缺少實物條碼仍可按已確認 ERP 品號轉銷貨，但倉內作業前必須確認條碼。
- 每一輸出列最多 200 件，依使用者目前 ECOUNT 序號／批號操作限制設定。450 件輸出 200／200／50。序號／批號欄維持空白，供人員在 ECOUNT 自行選擇；不產生或推測 SN。
- 含稅成交總額先加總，再依件數按累計比例分配到各列，保留每一分。單價是四捨五入兩位的加權均價，核對基準為明細稅前金額＋營業稅，不以顯示單價乘數量重建總額。ERP 匯入需保留明細金額；若 ERP 自動重算造成差額，回匯會阻擋，不會自動接受差額。
- 各輸出列重新計算含稅 5% 的稅前金額及營業稅，計算版本 `twd-vat5-product-200-v1`。因四捨五入次數改變，新舊格式的稅前／稅額可能不同，含稅總額必須一致。原始訂單金額與原逐筆銷貨列不覆寫。
- 原 27 欄不變：K 欄仍是批次；商城訂單編號欄在彙總列填本批 WMS 號；來源明細號填穩定 `AG-…` 彙總列號。`salesLayout` 保存每一列到來源平台／店鋪／訂單／明細的數量及原成交金額分配，核對 Excel 新增「彙總銷貨對照」。銷貨匯入檔仍只有一個工作表，避免誤匯核對頁。
- 回匯必須保留 `AG-…` 及本批號，按保存的彙總數量、金額及品項核對。回傳 SN 沿用原 12／13 碼英數、摘要與專用欄一致性及重複檢查；依保存的來源順序及 ERP 回傳的 SN 順序預先分配到原訂單，工作單必須掃到分配的 SN 才能完成。這是待揀指定，不是已完成出貨。一般生產 LOT、箱號、棧板的新語法及任意更換分配另行實作，不把 LOT 文字自行當成商品 SN。
- 已保存／已匯入 ECOUNT 的舊批次不自動升級、不重複送單。若重新上傳原訂單切換格式，既有來源防重會提示使用原批次。正式銷貨的修改／撤回需核對原 ERP 單據後另行操作。

真實資料本機重算：SHOPLINE #6 的 28 列變 15 列，44 件、30,766 元不變，彙總後試算稅前 29,302／營業稅 1,464；Shopify #4 的 49 列（含運費）變 24 列，含稅 35,852 元不變。沒有改寫這兩批 DEV 保存資料，也沒有重新提交 ECOUNT。原 `ESD007E.xlsx` 缺少品號、來源明細及稅額，仍不能完成可靠回匯；未宣稱原生 ERP 彙總匯入與 SN 回匯已實測通過。

新增建議報表「WMS銷貨回傳核對」。頁面提供只有欄名的空白 XLSX；它不是待上傳銷貨檔，更不是 ERP 成功回執。

| WMS 接受的欄名 | ECOUNT 對應資料 |
|---|---|
| ECOUNT實際銷貨單號 | 已儲存銷貨的日期-號碼，如 2026/09/16 -27，不可填 WMS 批次號 |
| WMS批次號 | 銷貨單單號（現行上傳 K 欄） |
| 客戶/供應商編碼 | 實際銷貨客戶碼，保留前導零 |
| 發貨倉庫 | 倉庫編碼，如 003，不是倉庫名稱 |
| 交易類型 | 交易類型編碼，現行含稅 5% 是 11 |
| 平台、店鋪、商城訂單編號、來源明細號 | 現行銷貨自訂欄位，各商品列都保留 |
| 品項編碼、數量 | ERP 明細的品號與件數 |
| 稅前價格、營業稅、含稅金額 | 每列金額；含稅金額＝該列稅前＋該列稅額，不用已四捨五入的單價重新乘回 |
| 國際條碼 | 選填；有填時必須和本批確認條碼一致，空白可用已確認的本批實物條碼 |
| 序號/批號、摘要 | 選填；沿用現有 SN 解析與衝突／重複／數量限制，不把一般備註當作 SN |

完整保留運費等非庫存列以核對金額，工作單只建立實物商品。第一個工作表單表、全批、不可混其他批次；缺列、重複、不同金額等全部不放行。現行只支援完整批次，拆單分批另行實作。

本次瀏覽器安全政策阻擋另開 ECOUNT 銷貨明細頁，尚未替公司建立這份 ERP 匯出格式。需要實際報表驗證可選欄位與匯出名稱；不把自製範本當成原生 ERP 匯出驗收證據。原有 TEST 銷貨 WMS-20260916-C639 / 2026/09/16 -27 的稅前及稅額仍需修正核對，未再次提交扣庫存。

## 保留與界線

- 原始轉檔 snapshot 不變；補確認實物條碼只更新本批作業對照，留下操作者與前值，不建立 WMS 商品主檔。
- 舊理貨回匯批次保持原流程；新流程不可從舊理貨入口繞過銷貨核對。已連結舊工作單的批次不可再啟用新流程。
- 新批次未核對 ERP 前仍可依原二次確認刪除；核對後只可封存。封存保留工作資料及追溯。
- 新 migration 033 只新增資料表／欄位，舊單 warehouse_hold 預設 false；不自動放行舊批次，不修改 ERP 或帳務。
- 每個寫入命令綁定目前登入者與 UUID；刷新頁面仍保留待確認命令；重試同命令不再計數。同一批次鎖定與來源身分鎖避免併發重建。
- 紙本掃碼／印表機、實際 ERP 稅額與庫存、會計憑證、物流標籤仍需現場與 ERP 實測。箱號／棧板不在這次落地範圍，待使用者提供實物案例。

## 2026-09-17 舊批次彙總下載修正

使用者下載 C639 時仍拿到 28 列逐筆格式。原因是已保存批次的主要下載入口仍取原快照格式，並非依不同單價分組。主要入口改為「下載彙總銷貨檔」，包含批次卡片、批次明細與倉儲回傳頁；原格式收在「其他下載」。檔名明確區分 ECOUNT彙總銷貨匯入。

新增 ecount-grouped 下載類型，從不可變原批次重建彙總視圖，不修改 snapshot、不建立新批次。回傳以 AG 來源明細識別彙總格式，仍核對完整來源集合、数量及金額；原逐筆回執保留支援，混合兩種格式拒絕。
