# 異動警示與例外查詢介面

## 操作

- 例外總覽上方是查詢條件，不修改訂單。區分審核進度與訂單作業進度，選項全部中文；條件按「查詢」才套用，清除包含搜尋字詞。人員篩選可展開。
- 案件以整頁清單呈現，手機使用卡片。提供「查看並審核／查看並結案」、處理結果、無結果與載入失敗提示及每頁 100 筆分頁。查詢序號避免較舊回應覆蓋新結果。例外時間 API 明確傳 UTC instant，顯示台灣時間。
- 異動送審、核准、駁回、結案、作廢及 SN 更換沿用原有責任人分派：倉儲／all 管理員、superadmin、該訂單拋單者／申請者、揀貨員、裝箱員。發起人已有操作結果，不再對自己的操作播警示音。
- 全站顯示大型異動警示：訂單號、事件、原因、台灣時間及處理指示。稍後查看只收合；「我已知悉」是個人收件確認，不核准提案、不恢復作業、不影響別人的通知。
- 專用六段提示音與揀貨／裝箱／錯誤不同，沿用個人音色及音量；異動警示音有獨立開關，預設開啟。設定可試聽。瀏覽器未允許自動播放或音量為零時，大型提示提供「啟用並試聽警示音」。實體喇叭、系統靜音及現場可辨識程度仍須操作站試聽。
- 未知悉的通知由資料庫保留，15 秒輪詢、Socket、恢復網路／回到頁面時補取；同一頁面的相同通知不重複播報。已被後續異動取代的通知顯示歷史提示，不將舊停工指令冒充最新狀態。原有待審作業阻擋不變。

## 資料與 API

`029_order_change_alerts.sql` 新增 `order_change_notices`、`order_change_notice_recipients` 及未確認索引。通知與訂單變更在同一交易寫入，交易提交後才送 Socket；留言已讀或撤回不會消除作業警示。Migration 僅將部署時仍待審的訂單異動補入通知，不重放全部歷史案件。既有訂單、帳號、SN、數量與角色不更動。

- `GET /api/order-change-notices`：只回傳目前使用者未確認的通知，最新 50 筆與未確認總數；`is_current` 區分同訂單是否已有較新事件。
- `POST /api/order-change-notices/:noticeId/acknowledge`：只更新目前收件者，冪等；其他人不能代確認。正常留言已讀與作業通知知悉相互獨立。
