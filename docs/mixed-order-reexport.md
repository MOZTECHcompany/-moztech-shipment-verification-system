# 整份訂單重新轉檔

同一份 Shopify CSV 可以包含新訂單與已保存訂單。比對頁會列出新增、異動、相同的訂單；拋單員核對並確認尚未匯入 ECOUNT 後，一次保存並下載包含本次全部訂單的一份銷貨檔。未上傳的其他訂單保留原樣，不推定取消。

已出貨、已回匯、已開始倉庫作業或缺少完整來源與商品證據時，整份確認會被拒絕，不會先保存其中一部分。此操作不修改商城收款、不呼叫 ECOUNT 過帳，也不直接扣庫。

## 保存與回匯

- `scopeMode: uploaded-file-v2` 使用現有 draft-overwrite preview/confirm API。確認綁定完整檔案、來源即時核對、既有批次狀態、操作人員與 command UUID。
- 同一交易保存原單異動記錄、新單、完整輸出批次與來源版本對照。重試同一 UUID 讀取原結果；結果不明時不得換 UUID 重送。
- 原 canonical source ID、所屬 intake 與工作條碼保留。新輸出批次的 membership 選取本次檔案內的來源，避免搬移來源或把未上傳訂單帶進輸出。
- 下載、理貨回匯與倉庫操作重新驗證來源版本。歷史版本可查看，已失效的版本不能再次下載、回匯或建立任務。
- 回匯後仍使用既有理貨核對、held 工作單、列印、指派、預揀與放行流程。工作單只涵蓋本次完整輸出批次。
- 已納入完整輸出版本的收件資料異動須以最新版整份 CSV 重新比對，避免只改原 owner 而留下另一份地址。

## DEV 發布條件

Migration `042_marketplace_upload_scopes.sql` 為原來源新增 `draft_version`，另建完整輸出 membership。舊 migrations 不得重跑。`WMS_MIXED_REEXPORT_ENABLED` 預設關閉。

必須先更新所有可服務路由為相容且關閉寫入的版本，確認舊 runtime 已結束處理，再啟用 mixed gate。發布前後核對九服務；其他八服務設定與流量保持原樣。線上驗證不覆蓋實際出貨訂單。

本機 PostgreSQL 的完整合成流程與併發測試不等於真實 ECOUNT、實體掃碼或列印驗收。
