# ECOUNT 瀏覽器助手：實作與驗收界線

ECOUNT 公開 OAPI 不支援修改既有單據；本功能不呼叫 SaveSale、不重新匯入銷貨、不沖銷重建原單。ECOUNT 保留唯一正式銷貨／庫存過帳責任。

## 本次範圍

WMS 完成裝箱後，以既有明確綁定的「公司＋原銷貨單日期／號碼」排入持久工作。公司 Chrome 助手讀取原單，僅補註商品列的 `WMS箱號明細`，重新開啟讀回，再逐欄比對數量、金額、倉庫、SN、來源列及其他業務欄位。沒有綁定、混合正負數、未完成裝箱、異常待處理、同品號多列缺少來源識別等情況均不自動儲存。

入口為「設定 → ECOUNT → 箱號回寫助手」。同一位管理員／拋單人員保持 WMS 與 ECOUNT 登入，從擴充功能選擇並綁定 ECOUNT 分頁。掃碼作業不等待助手；關閉開關時完成掛鉤不增加 SQL。

本版本只有在「可確認確實尚未嘗試儲存」時允許修正後重試。儲存結果未知、連線中斷、助手重新啟動時，只能讀回確認，不得盲目再按儲存。恢復資訊依人員保存在此 WMS 網站的瀏覽器儲存區，跨關閉分頁保留；包含租約與箱號修改計畫，不包含 ECOUNT 密碼、Cookie、工作階段網址或完整原單快照。原登入人員重新登入後才能恢復，權限仍由伺服器重新確認；同瀏覽器的多個助手分頁使用 Web Locks 防止同時處理。

若原單已寫入而 WMS 隨後改單，只能依凍結的舊計畫與歷史綁定唯讀確認。結果為 `superseded_verified`：舊版已核對、新版尚未回寫；保留舊計畫及讀回稽核，解除原單未知工作阻擋，不修改新版 WMS 或再次儲存 ECOUNT。原單畫面中剛填入的文字、切換格式造成的新表單 ID 都不能當作已儲存的證據。

## 發布開關

- `ECOUNT_BROWSER_ASSISTANT_MODE=off`：預設關閉；不操作 ECOUNT。
- `preview`：僅產生並核對預覽，不儲存。
- `test`：另須 `ECOUNT_BROWSER_ASSISTANT_TEST_WRITE_ENABLED=true`、`ECOUNT_BROWSER_ASSISTANT_DOCUMENTS` 明確公司／日期單號允許清單，以及可驗證的專屬 TEST 畫面。只測試短文字上限 200 字，不推論正式欄位上限或並行保護。結果標示 `test_verified`。
- `live`：須實際驗收證據的 SHA256、已驗證的原生並行修改保護及文字欄長度證據。前後雜湊只能偵測覆寫，不能防止另一人同時編輯，因此不得用雜湊或測試綠燈代替原生保護。

不得從畫面自稱能力或假造公司代碼／版本欄位。公司、原單鎖定日期號碼及完整業務欄位須由實際 DOM 讀取；找不到就停止。助手不取得 WMS JWT、不讀 ECOUNT Cookie／密碼、不存帶工作階段的網址，不呼叫未公開的 ERP HTTP 介面。

## 資料與回復

Migration 044 只新增工作、指令回執與稽核事件三張表及索引；不改既有使用者、密碼、訂單、箱號、SN 或庫存。應用啟動只檢查 schema，仍由獨立 release job 明確套用 migration。

若發現異常，先將模式改為 `off`、停止助手；保留工作與回執。已嘗試儲存的單據先讀回核對，不能重新出貨、建立第二張銷貨單或覆蓋資料庫備份。不得刪除未知工作的稽核證據。

## 已授權真實 TEST 資料

2026/10/16 使用者明確授權建立一張獨立 TEST 銷貨單，測試後由使用者刪除：

| 類別 | 識別 |
| --- | --- |
| ECOUNT 原銷貨單 | **2026/10/16-2** |
| 公司代碼 | **900324**（使用者確認） |
| 自訂單號／測試代碼 | `TEST-WMS-20261016` |
| 客戶名稱 | TEST WMS自動回寫驗收－勿出貨勿開票 |
| 專用商品 | TEST WMS箱號回寫驗收－勿出貨 |
| 商品／客戶代碼 | `TEST-WMS-20261016` |
| 數量／單價／總額 | 25 件／0／0 |
| 發貨倉庫 | 003 工業店 |
| 理貨單對象 | 不使用 |

僅為專用 TEST 商品建立初次銷貨紀錄；不能把這次初次過帳與之後的文字補註混為一談。需比對 TEST 商品過帳前後餘量、原單修改紀錄及原數量。日常商品與其他銷貨單不在測試範圍。

目前狀態：已建立並查回 TEST 單。以正常 ECOUNT 畫面只改箱號文字、儲存、關閉後重開，數量仍為 25、單價及金額 0、批准狀態維持。TEST 商品在工業店的庫存補註前後均為 -25，差額 0；初次建立銷貨造成的 TEST 商品負餘量與這次文字補註已分開比對。

另以兩個正常 ECOUNT 視窗先開啟同張 TEST 單，第一視窗儲存 A 後，第二舊視窗嘗試儲存 B，ECOUNT 回覆「已被其他使用者修改過的憑證」並拒絕；重新開啟確認仍是 A、25 件與零金額。此證據限該 TEST 公司／表單，不推論其他格式、SN 明細或正式欄位長度。

實際助手安裝與自動儲存、正式自動回寫尚未驗收。現場 writer 目前只允許該 TEST 單的單列專用商品、25 件、零金額、無 SN、200 字內的箱號補註；安全庫存提示不自動確認。程式／隔離測試及手動 UI 補註結果不能替代助手驗收，也不代表已部署正式環境。

公司 Chrome 的真實驗收使用另一個明確標記的 `--real-ecount-test` 套件：只接受 `http://127.0.0.1:55780` 的隔離 WMS 與真實 ECOUNT，不匹配正式 WMS。Chrome 的 manifest 網址模式無法限定 localhost 埠，因此顯示 `127.0.0.1` 權限；執行時仍逐次驗證精確 origin、助手路徑、操作人員與原生 document identity。測試資料庫不使用 Cloud SQL 或正式秘密。安裝須依瀏覽器操作規則取得當次確認。

正式啟用前還需補齊實際助手存檔／關窗／重新查回、一般商品與 SN／同品號多列定位、正式欄位長度及長時間運行驗收。現有 plan fingerprint 是內容雜湊，並非伺服器簽章；正式許可應另使用可驗證、短效且綁定人員／原單／計畫的伺服器簽章，不能將同源橋接布林值視為授權證明。現場 adapter 的正式能力與 live 寫入仍保持關閉。

## 可重跑檢查

```sh
npm run test:unit --prefix backend
npm test --prefix frontend
npm test --prefix tools/ecount-browser-assistant
npm run build --prefix frontend
```

原生 PostgreSQL 與獨立 Chrome 的測試使用專用 loopback 資料庫、臨時 profile，不連正式 Cloud SQL 或使用者 ECOUNT。套件打包、安裝方式與限制見 `tools/ecount-browser-assistant/README.md`。實際安裝到使用者 Chrome 會新增 ECOUNT 頁面讀寫權限，必須於套件可審閱後取得該次安裝確認。
