# SHOPLINE / 1Shop 商城批次

## 人員流程

1. 上傳平台原始 Excel / CSV，選擇已保存店鋪。
2. 系統核對商品、出貨條件及金額；下載 ECOUNT 銷貨檔時保存來源明細與登入承辦人。
3. 人員將銷貨檔匯入 ECOUNT，確認並儲存實際銷貨，再匯出理貨／出貨明細。
4. 從原批次回匯；商品、數量、來源及適用金額核對成功後，建立尚未放行的逐筆工作單。
5. 倉儲主管收到批次待辦，列印預揀總表及全部訂單明細，指派預揀人員。
6. 預揀掃碼清點完成後放行。揀貨完成才開啟裝箱複檢，各階段綁定登入者。

下載銷貨檔、收到通知、列印，均不代表 ECOUNT 已扣庫存或 WMS 已出貨。

## 資料與權限

- 相同 ERP 品項與已確認條碼的數量、成交金額加總，單價採加權值，每列最多 200 件；逐筆來源分配另行保留。
- 含稅總額守恆，稅前金額與營業稅為整元；加權單價可能有顯示尾差，核對以明細金額為準。
- 品項編碼及條碼存為 Excel 文字，保留前導零、NEW 與尾碼；不猜測實物條碼。
- 回匯保留 SN／批號及摘要來源，ERP 彙總列還原至原始訂單。
- 拋單員／訂單管理員可轉檔及回匯；倉儲主管才可列印、指派及重設預揀。
- 批次通知採資料庫留存、各人已讀與每批每階段防重；socket 僅提示重新讀取，交易提交後才發送。

## API

店鋪的持久設定 `apiConnectionId` 選取後端連線；上傳檔案不能關閉已綁定查核。未綁定時明確採檔案模式。

- SHOPLINE：`WMS_SHOPLINE_ACCESS_TOKEN`、`WMS_SHOPLINE_MERCHANT_ID`、`WMS_SHOPLINE_HANDLE`、`WMS_SHOPLINE_CONNECTION_ID`。
- 1Shop：`WMS_1SHOP_STORES_JSON`，完整 account 精確選取；`WMS_1SHOP_SHOP_URLS_JSON` 提供各 account 已確認 HTTPS origin。display name 不用於識別店鋪或 ECOUNT 客戶。
- API 回傳現況核對完整 SKU、數量、折扣、運費及總額，寄送資料採最新 API；保存前重查並比較 fingerprint。
- 已確認取消、付款失敗或逾期的訂單保留排除原因；身分、已知狀態與完整金額仍須核對。
- IP 白名單、授權、逾時與無法可靠辨識的組合／退款等情況會阻擋；不退回舊檔、不以 0 單冒充查核成功。
- 僅讀取商城，沒有自動寫入 ECOUNT。
