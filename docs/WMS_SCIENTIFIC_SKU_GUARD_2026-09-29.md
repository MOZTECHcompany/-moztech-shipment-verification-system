# 科學記號貨號防錯

## 原因
2026-09-28 的 WMS-20260928-0F55 來源 CSV 已將 55 列商品的 SKU 寫為 `4.71E+12`（53 列、63 件）或 `4.71E+13`（2 列、2 件）。44 筆訂單皆符合出貨条件。來源有 28 個不同商品名稱，但無法據此推定完整品號或真正的商品種類數。WMS 原先允許人工確認這兩個錯誤來源碼並彙總，造成不同商品被合併。總件數 65、訂單總額 58,298 並未消失，商品身分已無法核對。

## 修正
- Shopify、SHOPLINE、1Shop 的原始貨號為科學記號或不安全數字時，解析立即阻擋，不嘗試展開或猜測。
- 底層解析與商品對照驗證也阻擋；手動確認對照不能繞過。
- 保存批次再次產生銷貨檔及倉庫放行對照時重新驗證，避免舊錯誤批次再次使用。
- 完整文字貨號、前導零、NEW 前綴、尾碼和可精確表示的數字品號保留；既有同商品數量／金額彙總及 200 件拆列規則不變。

## 驗證
- 以使用者實際 CSV 重播：修正前 44 訂單、55 商品列被解析成 2 個 SKU、65 件；修正後立即顯示科學記號錯誤。
- 前端 280 項測試；後端 284 項測試（Node experimental-vm-modules，供 Jest 呼叫原生 ESM 驗證函式）；前端建置通過。
- 真實訂單與原始檔不提交 Git。須從 Shopify 重新匯出保留完整 SKU 的檔案，才能重新產生可入帳／銷庫的銷貨檔。
- 不更改或刪除原批次，不寫入 ECOUNT；已匯入 ECOUNT 的錯誤單需先核對原單，不應直接重複匯入。
