# ECOUNT 銷貨金額與責任追溯（2026-09-17）

## 修正

- Shopify、SHOPLINE、1Shop 共用 27 欄輸出。線上匯入欄位順序不變，僅一張「銷貨匯入」工作表。
- 修正先前只提供含稅單價、期待 ERP 自行計稅，實際匯入卻保存零稅前／零營業稅的問題。
- 限原有 TWD、營業稅 11、含稅 5% 模式。每列 VAT = 含稅列金額 ÷ 21，四捨五入至元；稅前列金額 = 含稅列金額 − VAT。稅前單價顯示兩位小數，列金額直接輸出，不以已四捨五入單價重算列金額。
- 原始訂單金額及折扣分攤保留；每列、每筆來源訂單與批次總額核對。逐列計稅可能與整單一次計稅有尾差，實際 ECOUNT 入帳結果仍須核對。
- 計稅版本 `twd-vat5-line-v1` 寫入快照。舊批次只有在原金額三欄全部空白／零、來源訂單及 TWD 稅制齊全且總額吻合時，於下載時補算；不改寫歷史快照、不新建批次。已有不同金額或未知版本則阻擋。
- 原本已送 ERP 的批次必須核對原單，重新下載不代表可以再次匯入扣庫存。

## 責任人與 SN

- WMS 轉檔建立者由 API 登入身分保存；理貨回匯操作人由原有 operation_logs.user_id 記錄。
- 新增選填專案負責人、業務負責人、ECOUNT 承辦人及專案編碼。ERP 編碼須人工核對後確認，不以 WMS 帳號代替；共用店鋪設定可保存這些預設值。
- 正常新批次摘要預設空白；可填本批共用備註。各商品的 SN 請填下載檔的「序號/批號」或「摘要」，不可填共用 SN。
- 新來源格式回匯支援既有摘要 SN 文法（12 或 13 位英數字、既有分隔／連寫形式）。兩欄均有 SN 必須一致；數量不符、格式錯誤或重複仍拒絕整次匯入。
- 原摘要、原序號欄、辨識來源及 SN 列表記入該子訂單的匯入日誌。一般備註不建立 SN。
- 「B 欄序號」是銷貨分組，「K 欄銷貨單單號」是批次追蹤；不是商品 SN，也不是工廠批號。箱號、棧板、任意格式批號管理未包含於本次。
- 預揀／明細下載增加「金額與追溯」工作表，記錄責任人、計稅方式、來源編號及逐列金額。
