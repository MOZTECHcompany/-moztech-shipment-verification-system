# 商城轉檔與 Shopify 即時查核

## 人員操作

1. 上傳商城原始訂單。已設定的店鋪自動帶入；有多個店鋪時選擇一次。
2. 修正系統指出的異常，下載銷貨檔。下載前保存批次、來源訂單及配送資料。
3. 將銷貨檔上傳 ECOUNT 並儲存；下載本批理貨／出貨單回匯 WMS。
4. 倉儲主管核對後一鍵列印預揀總表與逐筆訂單；預揀完成後放行各筆揀貨及裝箱複檢。

下載銷貨檔不是 ECOUNT 入帳、銷庫或物流交寄的成功證明。

## Shopify 連線

WMS 使用官方 Admin GraphQL API `2026-07`，固定查詢訂單。Shopify CLI 是開發工具，日常操作不需要人員執行 CLI。

後端環境設定：`WMS_SHOPIFY_SHOP`、`WMS_SHOPIFY_API_VERSION`、`WMS_SHOPIFY_ACCESS_TOKEN`。
金鑰只以 Secret Manager 引用注入後端；前端、Git、下載檔及日誌均不得包含金鑰。
DEV 使用公司現有 Shopify 授權連線，程式只提供固定的讀取查詢，沒有 Shopify 或 ECOUNT 寫入操作。
現有連線本身可能具有其他應用所需的寫入權限；不得把它描述為只具唯讀範圍的金鑰。

支援查核用 CLI：`npm run shopify:check -- /絕對路徑/訂單.csv`。使用同一組後端環境設定，只輸出非配送的查核摘要，不保存批次。
既有 Shopify CLI 已以關閉自動升級／分析的模式確認可執行。

## 核對規則

- 訂單 ID、訂單名稱及店鋪精確匹配；不靠 Outstanding Balance、最後一行或相似貨號猜測商品。
- 最新 `currentQuantity` 為零的舊商品移除；以目前有效明細、目前總額和實際付款／出貨狀態轉檔。
- 整單取消、有效數量為零時，保留取消證據及排除原因，不恢復 CSV 商品或金額；整批沒有有效商品時不能下載銷貨檔。
- API 查核失敗不退回過期 CSV。下載前重新讀取，資料變更則重新核對，不直接保存舊結果。
- 原始 CSV 與 API 查核證據保留於批次，已保存檔案不因後續平台變更而重算。
- 相同品項彙總數量及成交金額，不以不同單價拆群；每列最多 200 件。單價為加權均價。
- 稅前價格與營業稅為整數元。訂單含稅總額必須是整數元；折扣分攤產生的商品尾差依原成交金額穩定分配，不改訂單總額。原始分攤金額保留供追溯。
- 整數稅額規則適用新批次；歷史批次沿用已保存的計算版本，不改寫原有銷貨檔。
- Shopify 與 ECOUNT 同時提供條碼時必須一致；缺少實物條碼不偽造。ECOUNT 品號、NEW 前綴和尾碼完整保留，停用品項阻擋。
- 部分出貨、退款、另列稅額／附加費、外幣或資料不一致需個別核對，不自行推算待出貨金額。
- 收件資料只保存出貨必需欄位，不保存 IP、付款卡號、帳單地址等無關資料。

## 環境與驗收

本次僅更新 DEV，沒有資料庫結構遷移，也沒有更改正式 WMS 流量。
單元測試及檔案核對不能取代 ECOUNT 實際匯入、倉庫印單與掃碼驗收。
1Shop 仍需確認店鋪及 ECOUNT 客戶編碼，並提供符合出貨條件的訂單；目前提供的樣本為未付款或已過期，不能當作正常銷庫驗收成功。
三平台真實 ECOUNT 匯入、銷庫、回匯及倉庫實體列印掃碼尚未全部驗收。
